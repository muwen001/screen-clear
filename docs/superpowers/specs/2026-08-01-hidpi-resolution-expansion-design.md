# ScreenClear HiDPI 分辨率扩展设计

日期：2026-08-01

状态：已获用户批准

## 目标

让目标外接显示器同时具备以下逻辑 HiDPI 模式：

- 1920×1080 @2x，渲染尺寸 3840×2160；
- 2560×1440 @2x，渲染尺寸 5120×2880。

1920×1080 已在当前源码的生成列表中，但本机已安装的旧 override 不含该条目；2560×1440 尚未在源码中定义。本次扩展必须同时解决新安装与旧配置升级，且不增加新的预设按钮。模式生效后只出现在“其他可用模式”列表。

## 当前状态

目标文件固定为：

`/Library/Displays/Contents/Resources/Overrides/DisplayVendorID-5e3/DisplayProductID-2490`

目标显示器标识为 vendor 1507（0x5e3）、product 9360（0x2490）。当前应用只按“文件是否存在”判断 override 已安装，无法识别内容是否过期。本机现有文件只含 2880×1620 与 3200×1800 两个渲染条目，因此升级后的应用必须显示更新入口，而不能继续显示为“已解锁”。

## 范围

### 包含

- 集中定义全部由 ScreenClear 管理的 HiDPI override 条目；
- 新增 5120×2880 渲染条目，并确保 3840×2160 条目存在；
- 保留现有 2880×1620、3200×1800 条目；
- 检查现有 plist 内容并区分未安装、最新、过期、无效；
- 将缺失条目合并到可识别的旧配置，保留额外模式和未知 plist 字段；
- 通过管理员授权安全安装或更新 override；
- 更新生效轮询、状态文案、自检、README 和自动测试；
- 重新编译、打包并安装应用。

### 不包含

- 新增 2560×1440 预设按钮；
- 应用启动时自动写入系统 override；
- 自动切换当前显示模式；
- 支持新的显示器 vendor/product；
- 保证 macOS、GPU、线缆或显示器一定接受 5120×2880 渲染模式。

## 方案选择

采用“集中模式目录 + 内容级升级检测”。不采用分散硬编码，因为生成、轮询和 UI 状态会再次失同步；不采用启动时自动更新，因为它会意外触发管理员授权并修改系统状态。

## 模式目录

`OverrideBuilder` 持有一份有稳定顺序、可测试的模式目录。每个条目同时描述逻辑尺寸和渲染尺寸：

| 逻辑尺寸 | 渲染尺寸 | 用途 |
| --- | --- | --- |
| 1440×810 | 2880×1620 | 保留现有“均衡”模式 |
| 1600×900 | 3200×1800 | 保留现有“更多空间”模式 |
| 1920×1080 | 3840×2160 | 本次要求的 1080p HiDPI |
| 2560×1440 | 5120×2880 | 本次新增的 1440p HiDPI |

plist 编码仍使用 `base64(4B 大端渲染宽, 4B 大端渲染高, 0x00)`。生成 plist、比较已安装内容、合并缺失条目和生效轮询都必须使用同一目录，不再各自维护尺寸数组或字符串集合。

## 配置状态

应用刷新时只读目标文件并生成以下状态：

- `missing`：目标文件不存在；
- `current`：vendor/product 正确，且四个目录条目均存在；额外条目允许存在；
- `outdated`：vendor/product 正确、plist 可解析，但缺少一个或多个目录条目；
- `invalid(reason)`：文件不可读、plist 无法解析、根对象结构错误、标识不匹配或 `scale-resolutions` 类型错误。

“最新”采用必需条目是已安装条目的子集这一语义，避免删除用户已有的额外模式。重复的二进制条目在比较和合并时按 `Data` 值去重。

## 更新流程

1. `refresh()` 只读检测配置状态，不弹授权窗口、不写文件。
2. `missing` 时显示“解锁 HiDPI（需管理员密码）”。
3. `outdated` 时显示“更新 HiDPI 配置（新增 1080p / 1440p @2x，需管理员密码）”。
4. `current` 时显示配置已是最新，并保留现有移除入口。
5. `invalid` 时显示原因与“移除无效配置”入口；为避免破坏未知配置，不提供直接覆盖更新。
6. 新安装从模式目录生成规范 plist；旧配置更新则读取现有 plist、保留全部未知键和额外模式，仅追加缺失的目录条目。
7. 生成结果在普通权限下完成结构校验和编码往返校验，再写入应用拥有的唯一临时文件。
8. 管理员脚本在目标目录创建同文件系统的唯一暂存文件，使用 `plutil -lint` 验证，设置普通文件权限后以原子移动替换目标。任何替换前失败都保留旧文件；临时清理只限本次创建的明确路径。
9. 用户取消授权或管理员脚本失败时，应用恢复非忙碌状态并显示具体错误。

管理员授权只能由用户点击按钮触发。应用安装和启动本身不得写 override。

## 生效检测

写入成功后刷新显示模式并等待以下两个精确配置同时出现：

- logical 1920×1080、rendered 3840×2160、HiDPI；
- logical 2560×1440、rendered 5120×2880、HiDPI。

检测使用 `ModeEntry` 的逻辑尺寸、渲染尺寸和 HiDPI 标记，不以单独的像素字符串或“任一新模式出现”作为成功条件。若首次轮询未满足，沿用现有显示器休眠/唤醒重握手流程；超时后提示用户重插线缆或重启，不宣称更新已生效。

模式出现后不新增预设。现有“其他可用模式”按渲染像素面积排序，5120×2880 会自然进入可见列表。

## 组件边界

- `OverrideBuilder`：模式目录、条目编码/解码、规范 plist 生成、现有 plist 检查与无损合并；不访问真实系统路径。
- `OverrideInstaller`：读取目标文件、返回配置状态、管理唯一临时文件、执行管理员暂存与原子替换、移除配置；不维护分辨率列表。
- `AppModel`：将配置状态映射到 UI，发起安装/更新/移除，协调生效轮询；不重复硬编码渲染尺寸。
- `MenuContent`：按状态显示解锁、更新、最新或无效配置入口；不新增预设。
- `SelfTest`：对集中目录的全部条目执行编码往返和 plist 构建测试，只使用内存或临时目录。

## 错误处理与安全

- 无效或标识不匹配的现有配置不得被一键覆盖；
- 合并必须保留未知键、额外模式和原有 vendor/product；
- 写入前必须完成 plist 解析、条目往返和 `plutil` 校验；
- 管理员写入在替换前失败时不得改变旧文件；
- 测试不得读取后再修改真实 `/Library/Displays` 文件；
- 编译、打包和应用安装不得切换分辨率、更新 override、修改 LinkDescription 或 LaunchAgent；
- 5120×2880 是否被系统暴露取决于硬件和 macOS，失败时提供可操作提示而非伪成功。

## 测试设计

自动测试至少覆盖：

1. 5120×2880 条目的已知编码和解码往返；
2. 规范 plist 含四个唯一条目及正确 vendor/product；
3. 仅有旧两条目的 plist 被判定为 `outdated`；
4. 四个必需条目齐全且包含额外条目时被判定为 `current`；
5. 合并旧 plist 后补齐 3840×2160、5120×2880，保留额外键和额外模式且不产生重复；
6. 损坏 plist、错误标识和错误 `scale-resolutions` 类型被判定为 `invalid`，且不会进入安装更新路径；
7. 生效检测只有在两个目标逻辑/渲染 HiDPI 配置都出现时通过；
8. Shell 管理员命令通过隔离夹具验证暂存、校验、原子替换以及替换前失败时旧文件不变；
9. 完整 `swift test`、Debug/Release 构建、打包脚本语法、App/ZIP 内容与签名门禁通过。

所有配置测试使用内存数据或唯一临时目录，不修改本机真实 override。

## 验收标准

- 旧两条目配置在应用中显示“需要更新”，而不是“已是最新”；
- 用户点击更新并批准管理员弹窗后，目标 plist 至少包含四个目录条目；
- 原有额外 plist 字段和模式不丢失；
- 模式重握手后，应用可在“其他可用模式”中展示 1920×1080 @2x 与 2560×1440 @2x；
- 任一目标模式缺失时，轮询不得报告完全生效；
- 应用重新编译、打包、安装并从 `/Applications/ScreenClear.app` 运行；
- 应用保持 ad-hoc 本地签名限制，Developer ID 签名与公证不在本次范围。
