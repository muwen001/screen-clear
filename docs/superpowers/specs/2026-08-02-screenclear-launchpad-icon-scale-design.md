# ScreenClear Launchpad 图标尺寸对齐设计

日期：2026-08-02

状态：视觉方向已获用户批准；本实现说明待用户审阅

## 背景与目标

用户在 Launchpad 中将 ScreenClear 与本机 ZCode 图标并排比较后，选择将 **应用图标外框和内部图形一起** 缩小，并采用“整体等比缩放”的方案。目标是在不改变 A 款蓝紫显示器图标的识别性、配色或中心位置的前提下，让其可见轮廓的占画布比例更接近 ZCode。

当前 ScreenClear 的主画板以 128×128 母版坐标绘制，彩色圆角方形为 `x=5…123`、宽高 118 px，约占画布的 92.2%。ZCode 的可见外框约占 83% 画布，周围留白明显更多。目标为将 ScreenClear 的整个可见构图压缩到约 83%，在 Launchpad 的网格中呈现相近的视觉重量。

## 已确认的视觉方案

### 总体比例与定位

- 以图标几何中心 `(64, 64)` 为锚点，对整个应用图标画面应用 `0.90` 的等比缩放；
- 128 px 母版中，现有背景由 `5…123` 变为约 `10.9…117.1`，宽高约 106.2 px（约 83.0% 画布）；
- 蓝紫圆角外框、白色显示器、底座、屏幕内填充、浅青闪光与相应笔画全部使用同一个变换，因此相互比例、层级和中心关系保持不变；
- 不单独收缩外框，也不单独移动或重绘显示器/闪光；这样能避免外框变小而内部图形显得拥挤或失衡。

### 常规尺寸（32 px 至 1024 px）

常规 PNG 继续以现有 128 px 参数化母版为唯一视觉来源。渲染时，在已完成“像素尺寸 ÷ 128”归一化之后，再围绕 `(64, 64)` 应用中心缩放，并调用现有 `drawAppIcon`。渐变裁切、圆角、显示器描边、底座和闪光都处在同一图形上下文中，以确保它们一并缩放。

这保留既有的颜色、圆角比例和小尺寸线宽策略；不复制一套新的常规尺寸坐标，也不修改菜单栏资源。

### 16 px 紧凑变体

16 px 仍保留专用的紧凑绘制路径，而非退回到机械缩放的常规母版。该路径的彩色外框围绕 `(8, 8)` 采用 `0.90` 中心缩放：现有 14.75 px 的彩色外框名义上变为约 13.28 px（约 83%），并保留约 1.36 px 的安全边距。

显示器、支架和闪光使用这一缩放后的目标位置做最近像素对齐，而不保留会把白色边框混成半透明的子像素坐标：显示器外框为 `x=3, y=5, 8×7`、内屏为 `x=4, y=6, 6×5`，底座缩至 `x=5, y=2, 5×2`，闪光以 `(12.5, 12.5)` 为像素中心。它是同一 90% 构图在 16 px 栅格上的可读等价物，不是对内部图形独立放大或重新定位。

由于 16 px 栅格化不可避免存在整像素量化，实现必须以解码后的 PNG 视觉结果为准，而不是只凭浮点坐标判断。最终图像仍须清楚保留：

- 白色显示器左右边、顶边和底边；
- 白色支架和底座；
- 右上角青色闪光，且不能退化为白色像素；
- 围绕图标的透明留白。

测试中的像素区域与变异 fixture 会按新渲染结果重新标定，保持“真实生成的图像 + 有意破坏后的失败证明”这一测试方法。

### 菜单栏图标

`MenuBarIcon.pdf`、菜单栏模板加载逻辑和 SF Symbol 回退路径不做视觉或尺寸变更。该资源服务于菜单栏而非 Launchpad，继续由 macOS 按状态和外观着色。

## 实现边界

### 会修改

- `Scripts/Icons/generate-icons.swift`：仅增加/调整应用图标绘制上下文的中心缩放；
- `Tests/Packaging/icon-generator-tests.sh`：更新 16 px 实像素可读性/变异断言，并新增或调整基于已解码高分辨率 PNG 的外框可见范围断言，使旧的约 92% 轮廓无法通过；
- 如验证发现打包校验需要知晓新的图像边界，可最小化调整相应测试；
- 重新生成资源、重新构建、重新打包并按现有受控流程安装 `/Applications/ScreenClear.app`。

### 不会修改

- 应用名称、Bundle ID、版本、`LSUIElement`、Dock/菜单栏行为或菜单栏 PDF；
- 图标文件格式、生成事务、签名、ZIP 布局和资源发布路径；
- HiDPI override、实际显示模式、`LinkDescription`、LaunchAgent、显示器配置或 Finder/Launch Services 缓存；
- 用户现有的无关工作树改动或安装以外的系统状态。

## 自动验证设计

1. 生成器仍须生成所有十个标准 `.iconset` PNG、非空 `.icns` 与有效 PDF，并保持失败注入时不发布半成品；
2. 高分辨率实际 PNG 的中心行/列将被解码检查：不透明蓝紫背景的连续主体必须位于目标中心带（约 83% 宽高、约 8.5% 四周留白），而旧的约 92% 轮廓必须触发失败；断言只读生成输出，不从生产代码推导；
3. 16 px 检查继续在解码 PNG 上验证显示器四边、支架/底座和青色闪光；两种受控变异仍须分别导致“顶边缺失”和“闪光缺失”失败；
4. 运行完整现有单元测试、Debug/Release 构建、图标生成测试、打包/归档/发布事务测试；
5. 按既有安装验收重新验证 `/Applications/ScreenClear.app` 的 `CFBundleIconFile`、图标资源、哈希、严格签名和精确运行路径；
6. 安装过程继续取证确认显示模式、`LinkDescription`、HiDPI override 与 LaunchAgent 不被本任务改动；不清除 Finder 或 Launch Services 缓存。

## 验收标准

- ScreenClear 在 Launchpad 中的蓝紫应用图标可见外框约占画布 83%，与本机 ZCode 的外框视觉重量接近；
- 显示器、支架与闪光相对外框等比缩小，构图居中、清晰、无裁切；
- 16 px、32 px 和 1024 px 图标均保持可辨认的白色显示器和青色闪光；
- 菜单栏图标及其回退行为不变；
- 构建、打包、签名、安装和既有安全约束全部通过，且不触碰 HiDPI/显示配置相关系统状态。
